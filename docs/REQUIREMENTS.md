# 論文投稿前データ照合AIシステム — 要件定義書

## 1.1 システム概要・背景と目的

本システムの目的は、**広く生命科学・医学生物学の論文投稿前検証を行い、研究公正上・PubPeer 上で問題視されやすい不整合を未然に防ぐ**ことである。

開発では過去の指摘事例（`check_reference/`）と実データ（例: `input/private_benchmark/`）、および研究公正関連文献・**公式オープンデータ**（Retraction Watch / Crossref、ORI、COPE 類型）を **benchmark・ネタ帳・回帰** に用いるが、**照合エンジンは特定データセット専用ではない**。任意の原稿・生データ・Figure セットに対して、`fixtures/patterns/pubpeer_patterns.json` に定義した汎用パターンで動作すること。**PubPeer サイトの自動クロールは行わない**。RW Crossref 公式 Git／API 等の許諾データは可（[DETECTION_AND_MODELS.md](DETECTION_AND_MODELS.md) §1.2）。benchmark への過適合禁止などの設計ルールは [ARCHITECTURE.md](ARCHITECTURE.md)「設計ルール」。

### 1.1.1 カタログ倫理の絶対ルール

ネタ帳・カタログ拡充では次を **例外なく守る**（正本: [DETECTION_AND_MODELS.md](DETECTION_AND_MODELS.md) 冒頭、`catalog_policy.absolute_rules`）:

1. **表現を取らない** — コメント原文・長い引用・PDF／図の再配布なし（git / Issue / PR / 配布物）。
2. **アイデア／検査仕様に抽象化する** — `abstract_rule` / `pattern_id` のみ。有罪断定・告発文は入れない。
3. **コメント者を名指し・攻撃しない** — カタログは方法論。

対象となる不整合の例:

- 生データとグラフの齟齬
- 同一コード流用によるデータの取り違え
- サンプルサイズ $n$ 数の記載ミス
- 統計手法の齟齬
- 画像の意図しない重複や過去論文からの例示画像の引用漏れ

## 1.2.1 開発の絶対条件 — 読む＝LLM、比べる＝機械

広く配布する前提で、次を **崩してはならない**:

| 役割 | 担当 | やってよいこと | やってはいけないこと |
|------|------|----------------|----------------------|
| **読む** | ローカル LLM/VLM | Legend・本文・Fig チャンクからパネル／n／群／出典などの **チェック項目 JSON** を抽出する。Fig 画像のパネル地図（VLM） | 論文ごとに正規表現ルールを増やし続けること。自然言語で「有罪／無罪」を最終判定すること |
| **比べる** | 決定論エンジン | 表行数・群ベクトル・DAG・画像類似度などで JSON／数値を突合し **Warning を確定** | LLM 出力だけを根拠に Warning を確定すること |

- 規則ベース Legend パーサは **フォールバック／安全網**に限定する。
- 不正検知用分類器の学習は行わない。LoRA は抽出スキーマが多様な公開 Legend で繰り返し破綻したときのみ検討（製品必須にしない）。

詳細・精度向上の指針: [DETECTION_AND_MODELS.md](DETECTION_AND_MODELS.md) §4–§5。


## 1.3 入力データ仕様

```
【入力ファイル群】
├── スクリプト / 設定
│   ├── R スクリプト (.R)
│   ├── Python スクリプト / ノートブック (.py, .ipynb)
│   └── 設定ファイル (.yaml, .yml)
├── 実験生データ
│   ├── 表形式データ (.xlsx, .csv)
│   └── コンフォーカル顕微鏡画像 (.czi, .lif)
└── 論文原稿・図表
    ├── 原稿ファイル (.docx 推奨 / .pdf 可)
    └── 論文図表 (.pdf)
```

原稿は **Word（`.docx`）を推奨**する。PDF（proof 原稿・掲載版など）も受け付ける。Word が無い場合は PDF の埋め込みテキストから段落を復元し（ヘッダー・フッターと図中ラベルの除去、段組みで途切れた段落の連結、Legend の分離、上付き引用番号の `[n]` 化）、Legend の n・本文の統計記載・参考文献も Word と同じ規則で読む。段組みの復元に頼るぶん Word より取りこぼしが出やすい。テキスト層の無いスキャンページは Tesseract で OCR する（`install.sh` が OS のパッケージ管理で任意導入。`PRE_PEER_CHECKER_SKIP_OCR=1` で省略）。導入できなかった環境では、読めなかったページをカバレッジに示す。Word と PDF が両方ある場合は Word を優先する（`parsers/manuscript_text.py`）。

実験データは **`data/` 直下に並べず、実験一つ分を 1 サブフォルダにまとめる**（絶対条件）。フォルダ名は `Fig1` / `Fig2` / `FigS1` を推奨する。突合はこの実験単位フォルダを優先し、誤配置でも数値指紋・n+群の一意一致があれば横断する。n だけの弱い手がかりでは別 Fig フォルダへ飛ばない。照合開始をフォルダ未整備だけで拒否はしない。



## 1.4 検証項目および出力アクション仕様

出力はすべて **Warning** に統一し、細分類タグを付与する。


| Warning 細分類               | 検知トリガー・具体例                              | 照合元 / 照合先                      |
| ------------------------- | --------------------------------------- | ------------------------------ |
| Warning [データ取り違え]         | 異なる実験系や別条件の Fig で、参照変数ミスにより同一データが流用     | スクリプト / Excel / Fig PDF        |
| Warning [設定・アノテーション不整合]   | YAML のサンプル数・群定義とデータフレーム行数や Word 条件名が不一致 | .yaml / 生データ / Word本文          |
| Warning [実験データとの不一致]      | 再計算した平均値・SD・$p$ 値が Word 記載と不一致          | 生データ / スクリプト / Word            |
| Warning [サンプルサイズ記載誤記]     | レジェンドの $n$ と生データ・スクリプト行数が異なる            | 生データ・コード / Word Legend         |
| Warning [統計手法の不整合]        | 3群以上で多重比較なし t 検定、対応のないデータに対応あり検定など      | 生データ構造 / Word本文                |
| Warning [画像重複・再利用（要出典確認）] | 同一論文内別パネル、または過去論文画像と一致。出典確認             | czi / lif / TIFF / Word Legend |
| Warning [コントロール群共有]       | 複数 Fig パネルで同一 Negative Control が共有      | 生データ・画像 / Word本文               |
| Warning [表記揺れ・参照不整合]      | 「Fig. 1C」の記述と実際のパネルラベル・Genotype が不一致    | Word本文 / Fig PDFラベル            |
| Warning [有効桁・数値表示]        | 比・正規化由来の値が有効桁を超える桁数のまま（1/3→0.3333 等）。Methods への明記か丸めを促す | 生データ（グラフ用表） / Word本文 |
